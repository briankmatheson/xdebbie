feat: Add auto-discovery and leader election (v0.3.0)

Implement zero-configuration clustering with multicast peer discovery
and Bully algorithm leader election.

Features Added:
- Multicast discovery on 239.0.0.42:7442 (UDP)
- ANNOUNCE messages every 5s with node capabilities
- HEARTBEAT messages every 1s for liveness
- Leader election with score-based ranking (uptime + capacity + load)
- Automatic failover in <15s on leader failure
- High availability with no single point of failure

Architecture:
- New modules: discovery/ and election/
- Discovery engine runs as async tokio task
- Election state machine with 4 states (Inactive, Follower, Election, Leader)
- Score calculation: 0-3501 points (uptime 0-1000, capacity 0-1000, load 0-1000, incumbent +500, UUID 0-1)
- Multicast TTL=1 for LAN-only operation

Implementation:
- discovery/engine.rs (345 lines): Main discovery orchestrator
- discovery/messages.rs (75 lines): Protocol message definitions
- discovery/multicast.rs (122 lines): UDP multicast socket wrapper
- discovery/peer.rs (106 lines): Peer tracking and management
- election/state.rs (284 lines): State machine with unit tests
- election/scoring.rs (183 lines): Score calculation with unit tests

Configuration:
- enable_discovery = true (default)
- multicast_addr = "239.0.0.42:7442" (default)
- Can disable for standalone operation

Testing:

- Package builds successfully: xdebbied_0.3.0-1_amd64.deb (3.5 MB)
- Binary sizes: xdebbied 9.1 MB (+200 KB), xdctl 6.6 MB (unchanged)
