# qfodufk8sd Bootstrap

This document describes the self-bootstrapping functionality added to `qfodufk8sd`, enabling single-binary deployment to stock Debian 13 systems.

## Overview

The bootstrap functionality automatically:

1. **Checks and installs dependencies** (libvirt, QEMU, cloud-localds)
2. **Ensures libvirtd is running** and enabled
3. **Discovers existing libvirt resources** (networks, storage pools)
4. **Creates default resources** if none exist:
   - Network: `qfodufk8s` on `192.168.100.0/24` with bridge `virbr-qfodufk8s`
   - Storage pool: `qfodufk8s` at `/var/lib/libvirt/qfodufk8s`
5. **Generates configuration** at `/etc/qfodufk8s/qfodufk8sd.toml`
6. **Generates secure API token** at `/etc/qfodufk8s/token`
7. **Creates environment file** at `~/.qfodufk8s_env` for `qfodufk8sctl`

## Usage

### Option 1: Explicit Bootstrap Command

Run the bootstrap command first, then start the server:

```bash
# As root (for dependency installation and libvirt access)
sudo qfodufk8sd bootstrap

# Start the server
sudo qfodufk8sd serve
```

### Option 2: Bootstrap on First Run

Start the server with the `--bootstrap` flag:

```bash
sudo qfodufk8sd serve --bootstrap
```

This will run bootstrap automatically before starting the server. If bootstrap fails, it will log a warning and continue (useful if already configured).

### Option 3: Default Serve (Existing Behavior)

If already bootstrapped, just run:

```bash
sudo qfodufk8sd serve
```

This assumes configuration and resources are already set up.

## Command-Line Options

### `qfodufk8sd bootstrap`

Bootstrap the system with automatic resource discovery and creation.

**Options:**

- `--force` - Overwrite existing configuration and token files
- `--uri <URI>` - Libvirt URI (default: `qemu:///system`)
- `--network <NAME>` - Network name to create (default: `qfodufk8s`)
- `--subnet <CIDR>` - Network subnet (default: `192.168.100.0/24`)
- `--pool <NAME>` - Storage pool name (default: `qfodufk8s`)
- `--pool-path <PATH>` - Storage pool path (default: `/var/lib/libvirt/qfodufk8s`)

**Examples:**

```bash
# Standard bootstrap
sudo qfodufk8sd bootstrap

# Custom network
sudo qfodufk8sd bootstrap --network internal --subnet 10.100.0.0/16

# Force re-bootstrap
sudo qfodufk8sd bootstrap --force
```

### `qfodufk8sd serve`

Start the API server and reconciler.

**Options:**

- `--bootstrap` - Run bootstrap before starting server
- `-c, --config <PATH>` - Configuration file path (default: `/etc/qfodufk8s/qfodufk8sd.toml`)

**Examples:**

```bash
# Start with bootstrap
sudo qfodufk8sd serve --bootstrap

# Start with custom config
sudo qfodufk8sd serve --config /tmp/my-config.toml
```

### `qfodufk8sd check`

Check connectivity to all configured hosts.

## Files Created

### Configuration: `/etc/qfodufk8s/qfodufk8sd.toml`

```toml
# qfodufk8sd configuration
# Auto-generated by qfodufk8sd bootstrap

listen = "0.0.0.0:7443"
state_file = "/var/lib/qfodufk8s/state.json"
token_file = "/etc/qfodufk8s/token"

policy = "spread"
reconcile_interval_secs = 5
host_stale_secs = 60

virsh = "virsh"
seed_command = ["cloud-localds", "--network-config={net}", "{out}", "{user}", "{meta}"]

[[hosts]]
name = "hostname"
uri = "qemu:///system"
failure_domain = "default"
bridge = "virbr-qfodufk8s"
storage_pool = "qfodufk8s"
cpu_overcommit = 2.0
mem_overcommit = 1.0
reserved_cpus = 2
reserved_memory_mib = 4096
control_plane_eligible = true
```

### Token: `/etc/qfodufk8s/token`

64-character hexadecimal token (32 random bytes), mode 0600:

```
a1b2c3d4e5f6...
```

### Environment: `~/.qfodufk8s_env`

```bash
# qfodufk8s environment variables
# Source this file: source ~/.qfodufk8s_env

export QFODUFK8S_URL=http://0.0.0.0:7443
export QFODUFK8S_TOKEN='a1b2c3d4e5f6...'
```

### State: `/var/lib/qfodufk8s/state.json`

Created at runtime to persist VM and host state.

## Libvirt Resources

### Network: `qfodufk8s`

- **Bridge**: `virbr-qfodufk8s`
- **Subnet**: `192.168.100.0/24`
- **DHCP Range**: `192.168.100.100` - `192.168.100.250`
- **Autostart**: Enabled

Created with:

```xml
<network>
  <name>qfodufk8s</name>
  <bridge name='virbr-qfodufk8s' stp='on' delay='0'/>
  <ip address='192.168.100.0' netmask='255.255.255.0'>
    <dhcp>
      <range start='192.168.100.100' end='192.168.100.250'/>
    </dhcp>
  </ip>
</network>
```

### Storage Pool: `qfodufk8s`

- **Type**: Directory
- **Path**: `/var/lib/libvirt/qfodufk8s`
- **Permissions**: 0711, owner:group 0:0
- **Autostart**: Enabled

Created with:

```xml
<pool type='dir'>
  <name>qfodufk8s</name>
  <target>
    <path>/var/lib/libvirt/qfodufk8s</path>
    <permissions>
      <mode>0711</mode>
      <owner>0</owner>
      <group>0</group>
    </permissions>
  </target>
</pool>
```

## Dependencies

The bootstrap process checks for and installs (if running as root):

- **libvirt-daemon-system** - Libvirt daemon and system utilities
- **libvirt-clients** - `virsh` command-line tool
- **qemu-kvm** - KVM virtualization
- **qemu-utils** - `qemu-img` and other utilities
- **cloud-image-utils** - `cloud-localds` for NoCloud seed generation

On Debian/Ubuntu, these are installed via:

```bash
sudo apt-get update
sudo apt-get install -y libvirt-daemon-system libvirt-clients qemu-kvm qemu-utils cloud-image-utils
```

## Bootstrap Process Flow

```
1. Check Dependencies
   ├─ Check for virsh, qemu-system-x86_64, qemu-img, cloud-localds
   ├─ If missing and root → apt-get install
   └─ If missing and not root → error with package list

2. Ensure libvirtd Running
   ├─ systemctl is-active libvirtd
   ├─ If not active and root → systemctl start libvirtd
   └─ systemctl enable libvirtd

3. Discover Resources
   ├─ virsh net-list → existing networks
   ├─ virsh pool-list → existing storage pools
   └─ Parse network bridges and pool paths

4. Create Resources (if needed)
   ├─ If no qfodufk8s network → virsh net-define + net-start + net-autostart
   └─ If no qfodufk8s pool → mkdir + virsh pool-define + pool-start + pool-autostart

5. Generate Configuration
   ├─ If config exists and not --force → skip
   ├─ Generate TOML from template with discovered resources
   └─ Write to /etc/qfodufk8s/qfodufk8sd.toml

6. Generate Token
   ├─ If token exists and not --force → reuse
   ├─ Generate 32 random bytes → hex encode
   ├─ Write to /etc/qfodufk8s/token with mode 0600
   └─ Write ~/.qfodufk8s_env with URL and token
```

## Resource Discovery

If libvirt networks or storage pools already exist, bootstrap will:

1. **Discover them** via `virsh net-list` and `virsh pool-list`
2. **Use the first available** network and pool in the generated configuration
3. **Skip creating defaults** if resources already exist

This allows bootstrap to work on systems with existing libvirt setups (e.g., `default` network and pool).

## Security Considerations

### Token Security

- Token is 32 random bytes (256 bits of entropy)
- Stored with mode 0600 (owner read/write only)
- Never logged or displayed except in environment file
- Bearer token authentication for all API requests

### Root Privileges

Bootstrap requires root for:

- Installing packages via `apt-get`
- Starting/enabling `libvirtd` service
- Creating libvirt networks (bridges require privileges)
- Writing to `/etc/qfodufk8s/` and `/var/lib/qfodufk8s/`

The server itself can run as root or as a user with libvirt group membership.

### Network Isolation

The default `qfodufk8s` network is NAT-isolated:

- VMs can reach external networks
- External networks cannot initiate connections to VMs
- VMs can communicate with each other on the bridge

## Integration with Cluster API

Once bootstrapped, qfodufk8sd can serve as the infrastructure provider for CAPQ (Cluster API Provider Qfodufk8s):

1. **Bootstrap** the host system:
   ```bash
   sudo qfodufk8sd bootstrap
   ```

2. **Start qfodufk8sd**:
   ```bash
   sudo qfodufk8sd serve
   ```

3. **Configure environment** for qfodufk8sctl:
   ```bash
   source ~/.qfodufk8s_env
   ```

4. **Verify connectivity**:
   ```bash
   qfodufk8sctl host ls
   ```

5. **Deploy CAPQ** to your management cluster and create `QfodufkCluster` resources

## Troubleshooting

### Bootstrap fails with "not running as root"

If not root, bootstrap cannot install dependencies or start services. Either:

- Run `sudo qfodufk8sd bootstrap`
- Manually install dependencies first, then run as non-root user in libvirt group

### Bootstrap fails with "Failed to connect to libvirt"

Ensure libvirtd is running:

```bash
sudo systemctl status libvirtd
sudo systemctl start libvirtd
```

### Network creation fails with "bridge already exists"

An existing bridge may conflict. Options:

- Use existing network: `qfodufk8sd bootstrap --network default`
- Choose different name: `qfodufk8sd bootstrap --network mynet`
- Remove conflicting bridge: `sudo ip link delete virbr-qfodufk8s`

### "Permission denied" when starting qfodufk8sd

Token file or state directory permissions may be wrong. Check:

```bash
ls -la /etc/qfodufk8s/
ls -la /var/lib/qfodufk8s/
```

Token should be mode 0600. If running as non-root, ensure user owns files.

## Comparison with Manual Setup

**Before (Manual)**:

```bash
# 1. Install dependencies
sudo apt-get update
sudo apt-get install -y libvirt-daemon-system libvirt-clients qemu-kvm qemu-utils cloud-image-utils

# 2. Start libvirtd
sudo systemctl start libvirtd
sudo systemctl enable libvirtd

# 3. Create network
cat > /tmp/network.xml <<EOF
<network>
  <name>qfodufk8s</name>
  <bridge name='virbr-qfodufk8s'/>
  <ip address='192.168.100.1' netmask='255.255.255.0'>
    <dhcp>
      <range start='192.168.100.100' end='192.168.100.250'/>
    </dhcp>
  </ip>
</network>
EOF
sudo virsh net-define /tmp/network.xml
sudo virsh net-start qfodufk8s
sudo virsh net-autostart qfodufk8s

# 4. Create storage pool
sudo mkdir -p /var/lib/libvirt/qfodufk8s
cat > /tmp/pool.xml <<EOF
<pool type='dir'>
  <name>qfodufk8s</name>
  <target>
    <path>/var/lib/libvirt/qfodufk8s</path>
  </target>
</pool>
EOF
sudo virsh pool-define /tmp/pool.xml
sudo virsh pool-start qfodufk8s
sudo virsh pool-autostart qfodufk8s

# 5. Create config
sudo mkdir -p /etc/qfodufk8s
sudo cat > /etc/qfodufk8s/qfodufk8sd.toml <<EOF
listen = "0.0.0.0:7443"
state_file = "/var/lib/qfodufk8s/state.json"
token_file = "/etc/qfodufk8s/token"

[[hosts]]
name = "$(hostname)"
uri = "qemu:///system"
bridge = "virbr-qfodufk8s"
storage_pool = "qfodufk8s"
cpu_overcommit = 2.0
mem_overcommit = 1.0
reserved_cpus = 2
reserved_memory_mib = 4096
EOF

# 6. Generate token
sudo mkdir -p /var/lib/qfodufk8s
TOKEN=$(openssl rand -hex 32)
echo "$TOKEN" | sudo tee /etc/qfodufk8s/token
sudo chmod 600 /etc/qfodufk8s/token

# 7. Create env file
cat > ~/.qfodufk8s_env <<EOF
export QFODUFK8S_URL=http://0.0.0.0:7443
export QFODUFK8S_TOKEN='$TOKEN'
EOF

# 8. Start server
sudo qfodufk8sd serve
```

**After (Bootstrap)**:

```bash
# One command does it all
sudo qfodufk8sd bootstrap
sudo qfodufk8sd serve
```
